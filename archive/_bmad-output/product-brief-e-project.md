# 产品简报：E-Project — 嵌入式 AI 自动开发平台

## 执行摘要

嵌入式开发至今仍是"人工密集型"工程：写完代码要手动编译、接线、下载、用示波器或逻辑分析仪观测输出、人脑判断结果、再回头改代码。AI 编程 Agent（如 Claude Code、Cursor）已经让前端和后端开发者体验到"写 → 跑 → 看 → 改"的全自动闭环，但嵌入式开发者被排除在外——因为 Agent 拿不到真实硬件的执行反馈。

E-Project 要打破这道墙。它是一块 **FPGA + ARM 板卡** 配合一套 **软件开发 Agent**，让 AI 第一次能够：自主编写嵌入式代码、通过 SWD 下载到目标 STM32 芯片、借助 FPGA 采集真实运行数据（GPIO 电平变化、UART 通信内容）、读取结果并自主迭代——实现"嵌入式领域的 Claude Code"。

这个时机恰到好处：AI 编程能力快速成熟，开源调试生态（OpenOCD）完善，FPGA 成本持续下降，而市场上没有任何产品把"调试探头 + 逻辑分析仪 + 协议模拟 + AI Agent API"整合在一起。

## 痛点

嵌入式开发者每天面临的真实场景：

- **手动闭环慢**：改一行寄存器配置 → 编译 → 接 J-Link 下载 → 接逻辑分析仪 → 目视检查波形 → 判断对错 → 再改。重复性高，一天循环几十次，大量时间消耗在"编译-下载-观测"的机械步骤上。
- **AI 帮不上忙**：Agent 可以帮你写代码，但它看不到 LED 有没有亮、UART 有没有输出正确的字符串、I2C 时序对不对。缺少硬件反馈，AI 只能写"可能正确"的代码。
- **工具割裂**：J-Link 管下载调试、Saleae 管信号抓取、Bus Pirate 管协议注入——三套硬件、三套软件、三条线，没有统一 API，无法自动化串联。
- **可观测性差**：芯片内部状态是黑盒，出了 bug 只能加打印、猜、试，效率极低。

独立开发者和小团队受害最深：他们没有专职测试团队，每个人既是写代码的、也是接线看波形的。

## 解决方案

E-Project 提供一块融合板卡和一个软件 Agent，通过板卡上的多维可观测性形成完整开发闭环：

**硬件（FPGA + ARM 板卡）：**
- **SWD 调试器**：替代 J-Link 基础功能，对目标 STM32 芯片进行下载、调试、Flash 编程，并可通过 SWD 读取目标芯片寄存器和内存值
- **FPGA 逻辑分析仪**：实时采集目标芯片 GPIO 信号，抓取时序和电平变化（IO 万用表模式）
- **协议模拟与监听**：FPGA 实现 UART 从机模拟，既能接收并校验目标芯片的串口输出，也能向其注入测试激励信号
- **FPGA bitstream 可升级**：协议支持随固件更新持续扩展，硬件"买一次，能力持续成长"

**软件（嵌入式开发 Agent）：**
- 类似 Claude Code 的交互式开发 Agent，理解嵌入式上下文
- 通过 arm-gcc 编译（V1 仅支持 arm-none-eabi-gcc 工具链，不支持 Keil/IAR）
- 通过板卡 SWD 下载、通过多种通道采集执行结果
- 对外暴露 API，支持脚本化和自动化集成

**Agent 判断正确性的多层机制：**

| 验证通道 | 工作方式 | 适用场景 |
|---------|---------|---------|
| GPIO 物理监测 | FPGA 采集 IO 电平变化，如同"IO 万用表" | LED 控制、开关状态、PWM 输出 |
| SWD 内存读取 | 通过调试接口读取寄存器值和 RAM 变量 | 内部状态验证、外设配置确认 |
| UART 从机模拟 | 板卡模拟串口从设备，接收并校验目标芯片输出 | 串口通信、日志输出验证 |
| 逻辑分析仪 | FPGA 精确时序采集，协议级解码 | 时序 bug、协议合规性检查 |

Agent 综合多通道数据判断代码是否达到预期，失败时自动分析原因并迭代。

**Agent 安全护栏与可观测性：**
- 每轮迭代生成结构化日志（代码变更 → 编译结果 → 下载状态 → 硬件反馈 → 判断依据），全程可回溯
- 设定最大迭代次数上限，防止 Agent 陷入死循环
- 对可能导致硬件风险的操作（如异常 GPIO 配置）给出警告并要求人工确认
- 开发者随时可手动接管任一步骤，Agent 支持优雅降级为半自动或纯手动模式

**闭环流程**：Agent 写代码 → arm-gcc 编译 → SWD 下载到目标芯片 → 多通道采集运行结果 → Agent 综合判断并迭代 → 循环直到通过

## 差异化优势

| 维度 | 现有方案 | E-Project |
|------|---------|-----------|
| 调试 | J-Link（手动操作） | SWD 调试 + Agent 自动化驱动 |
| 信号采集 | Saleae（独立工具） | FPGA 逻辑分析仪，API 直连 Agent |
| 协议交互 | Bus Pirate（手动命令） | FPGA 协议模拟，Agent 可编程控制 |
| AI 集成 | 无 | 原生 Agent 闭环，硬件反馈即 Agent 输入 |
| 统一性 | 三套硬件+三套软件 | 一块板 + 一个 Agent |
| 可升级性 | 固定功能硬件 | FPGA bitstream 升级，能力持续扩展 |
| 主动测试 | 被动观察为主 | FPGA 可主动注入激励信号，制造测试条件 |

**核心护城河**：不是单点工具的替代，而是**闭环体验**——市场上没有产品让 AI Agent 能"看到"硬件执行结果并自主迭代。每一轮 Agent 迭代产生的"代码模式 → 硬件行为"映射数据，长期构成嵌入式 AI 的独特数据资产。

## 目标用户

**主要用户：独立嵌入式开发者 & 小团队（≤10 人）**
- 使用 STM32 系列 MCU（Cortex-M3/M4/M33）
- 成本敏感，买不起或不愿意同时维护多套高端工具
- 追求效率，希望把重复的"编译-下载-观测-判断"循环交给 AI
- 技术能力强，愿意尝试新工具，熟悉 arm-gcc 工具链

**次要用户：嵌入式教育者 & 学生**
- 高校嵌入式课程中，学生接线调试耗时、助教资源不足
- E-Project 可作为"AI 助教"——学生写代码，Agent 自动验证并反馈
- 降低嵌入式入门门槛，院校采购场景付费意愿明确

**成功时刻（Aha Moment）**：Agent 自主完成了一个 GPIO 点灯程序的编写、编译、下载到真实 STM32 芯片、通过 FPGA 检测到 GPIO 电平变化确认正确——全程无需人工干预。

## 成功标准

- **V1 核心验证**：Agent 能独立完成 GPIO 控制程序的全自动"写 → 编译 → 下载 → 验证"闭环
- **流程自动化率**：编译-下载-基础验证环节实现 100% 无人值守
- **进阶指标**：Agent 能自动定位并修复 UART 通信 bug（通过串口从机模拟检测输出异常 → 结合逻辑分析仪定位时序问题 → 修改代码 → 重新验证）
- **可靠性**：Agent 迭代闭环成功率 ≥ 80%（GPIO 场景），每轮闭环无人工介入

## 范围

**V1（MVP）包含：**
- FPGA+ARM 板卡硬件设计与固件
- SWD 下载/调试功能（目标芯片：STM32 Cortex-M3/M4/M33）
- SWD 内存/寄存器读取
- FPGA 逻辑分析仪（GPIO 电平采集，IO 万用表模式）
- UART 协议监听与从机模拟
- 软件 Agent 核心（代码生成 → 编译 → 下载 → 多通道采集 → 判断 → 迭代）
- arm-none-eabi-gcc 工具链集成
- Agent 与板卡通信 API
- Agent 安全护栏（迭代上限、危险操作确认、手动接管）
- 迭代日志系统（全程可回溯）

**V1 工具链说明：** 仅支持 arm-none-eabi-gcc。Keil MDK、IAR、STM32CubeIDE 等不在 V1 范围内。

**V1 明确不包含：**
- I2C/SPI 协议模拟（V2，通过 FPGA bitstream 升级添加）
- Web/桌面端可视化 UI（V2）
- 多目标芯片同时支持
- 非 STM32 Cortex-M 芯片支持
- CI/CD 集成
- 模拟器件支持（DAC/ADC 模拟）

**关键风险与预验证：**
- **AI 嵌入式代码能力**：在硬件设计前，先用现有工具（J-Link + OpenOCD + arm-gcc + LLM API）手动编排一次完整闭环，验证 AI 对寄存器级代码的生成能力边界
- **SWD 兼容性**：STM32 各系列（M3/M4/M33）的 SWD 实现和 Flash 编程算法有差异，需逐型号适配验证
- **定价策略**：目标用户成本敏感，板卡 BOM 成本和售价需单独评估，确保低于用户已有工具总持有成本

## 愿景

如果 V1 验证了"AI + 硬件反馈闭环"的可行性，E-Project 的 2-3 年目标：

- **支持所有主流 MCU 架构**（Cortex-M/A、RISC-V、8051 等）
- **FPGA + 模拟器件覆盖 80% 的嵌入式自动化开发场景**
- **成为嵌入式领域的通用 AI 开发平台**——不只是调试工具，而是嵌入式开发的基础设施
- CI/CD 能力作为平台的自然延伸，支持硬件在环的持续集成与回归测试
- 开放生态：板卡通信协议文档化、采集数据支持标准格式导出、第三方可扩展协议支持和芯片适配
- Agent 迭代积累的"代码-硬件行为"数据集，持续反哺模型能力提升
